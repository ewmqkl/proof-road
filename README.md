# 证明之路 · 从命题逻辑到代数定理

一个**零依赖**的网页小游戏：玩家在 Fitch 式证明台上点选前提、应用自然演绎规则，一步步推出中学数学课本里的结论。
每一步都由一个形式化内核实时校验，推错会被明确拒绝。

当前进度：**L0 + L1 共 32 关**，其中 **30 关有标准证明与逐步提示**（另 2 关是开放练习）；
55 项自动化测试全部通过；解算器能独立搜出并验证 **26 / 32 关**的证明。

---

## 一、先看结论：为什么不是"纯命题逻辑"

这是设计上最关键的一点，也是调研后必须纠正的前提：

| 想证明的东西 | 需要的逻辑强度 |
|---|---|
| A → A、(A∧B) → A、分情况讨论、反证法 | **命题逻辑**（L0） |
| x + y = y + x、合并同类项、移项、绝对值 | **一阶等词逻辑 + 有序域公理**（L1） |
| 三角形内角和、平行线性质 | 一阶几何公理（Tarski / Hilbert，L2） |
| 极限、导数、实数完备性 | 二阶 / 集合论强度（不可一阶化，只能作公理层） |

所以引擎做成**三段式**，这也是 Lean 等系统的实际做法：

    玩家操作（一阶层）              内核翻译（命题层）                 判定
    选前提 → 点规则         →   把这一步化成蕴含式          →   结构化校验（毫秒级）
    ∀E / →E / ∧I …               （前提1 ∧ 前提2 → 结论）          不通过就拒绝

内核只接受**可靠的局部推理**：一步的结论必须由所选前提按某条规则的形状精确导出。
"代数化简（Ring）"这类看起来自动的规则也不是黑箱：它把等式两边化归为**同一个多项式的规范形式**，
合法性完全由域公理（交换、结合、分配、逆元）保证，等价于把这些公理自动用了一遍。

## 二、怎么玩

浏览器的 ES 模块策略不允许 file:// 下加载模块，请用自带的静态服务（零依赖，只用 Node 内置模块）：

    node tools/serve.mjs        # 然后打开 http://127.0.0.1:8788

**或者完全不开服务**：直接双击 `proof-road-standalone.html`。
那是把所有模块内联进一个文件的构建产物（约 114 KB，零外部依赖），
用 `node tools/build-single.mjs` 生成、`node tools/check-standalone.mjs` 验证。

界面操作：

1. 上方是**本关要证的结论**；
2. 左侧"可用事实"里**点选**若干条作为前提（再点一下取消）；
3. 右侧点一条**推理规则**：
   - 若这一步只有一种成立的结果，界面**直接替你落下**（例如 ∧E 取出的那一支正好是目标）；
   - 若有好几种可能，规则下方会出现**候选结果**按钮（如"取左边 / 取右边"），点一个即可；
   - 也可以自己在候选栏里**手写项或结果式**（回车确认），用来做中间步骤；
4. 通过就生成一条新的已推导事实；不通过会给出**具体原因**；
5. "打开假设"用于子证明（蕴含引入 / 否定引入 / 反证法都要先开子证明）；
6. "提示"按本关标准证明逐步给提示；"查看本关公理表"可展开公理。

**分情况讨论（∨E）怎么走**：选中一条析取再点 ∨E，界面会给出一个**引导卡**，
写清"两支各自要推出什么"，每支旁边有"开始这一支"按钮，点了就自动替你打开对应的子证明。
一支推完合上（用 →I / ¬I / ⊥C）后，回到引导卡会看到它标成 ✓；两支都 ✓ 之后，
再选中那条析取与两条结论点 ∨E 就收尾。左下角还有**子证明指示器**（"1. H1：A ／ 2. H2：¬B"），
随时能看到自己处在第几层、以及合上时该收哪一层。

**排中律**（A ∨ ¬A）不需要自己写式子：点排中律，界面会列出可用的取法；
如果目标形如 A ∨ B，它会自动挑出该对哪个命题取排中。

**证明记录**里子证明内的事实会按层次缩进，已经合上的整段变灰并标注"已合上"，
避免误以为还能引用。

进度存在浏览器 localStorage，可随时重置。

### 关卡一览

**L0 命题逻辑训练场（16 关）**：引用前提 → 蕴含引入 → 假言推理 → 合取引入/消去 →
析取引入/分情况讨论 → 否定引入 → 反证法 → 逆否命题 → 双重否定 → 骑士与骗子 →
三段论 → 等价引入 → 综合题（多步推理、排中律分情况）

**L1 代数证明（16 关）**：等式的对称/传递/等量代换 → 公理实例化（交换律、结合律）→
两边同时运算 → 合并同类项 → 完全平方 → 平方差 → 移项解方程 → 平方非负 → 绝对值 →
一次函数单调性 → 集合属于关系 → 综合题（复合式子上的公理应用）

## 四、内核设计要点

**de Bruijn 绑定**：量词不存变量名，只存索引（0 = 最内层）。因此"替换抓错变量"在**结构上不可能发生**，
不是靠小心，而是靠表示法。形如 ∀y, w + y = y + w 的结果由 instAll / closeAt 直接算出。

**作用域纪律（Fitch 风格）**：每条事实都记录它依赖了哪些假设。
蕴含引入只能合上**最内层**假设，结论仍带外层假设标签；合上后，依赖该假设的事实立即失效，不能再被引用。
所以嵌套子证明（比如逆否命题）必须真的嵌套着做，不能跨层取巧。

**形状精确匹配**：规则检查公式的形状。蕴含消去要求前提中有 A → B 且另一个前提与 A α 等价；
析取消去要求两支蕴含的结论**完全相同**。α 等价对项也成立（a = b 与 b = c 能正确串成 a = c）。

**量词实例化**：全称消去必须给出项，比如把 ∀a,b. a + b = b + a 用到 x、y 上——
这正是数学里"把普遍规律用到具体对象"的动作。界面提供"展开全称公理"一键生成候选实例。

## 五、自动搜证明（解算器）

除了手写关卡，工程里带一个**自动定理证明搜索器**：给一个定理（+可用规则 +公理集），它会自己把证明找出来，
并且**每一步都立刻用内核验证**，最后还会把整份计划在干净状态上重放一遍确认达阵。

    node tools/solve-cli.mjs                     # 给全部 28 关搜证明
    node tools/solve-cli.mjs L0-10 --depth 10    # 指定关卡与深度上限
    node tools/gen-proofs.mjs                    # 生成/刷新 src/data/found-proofs.js

**做法**：反向链接（从目标倒推）+ 迭代加深 + 节点/时间预算。招法按“目标形状”生成：
目标是蕴含就先假设前件再证后件；目标是合取就分成两个子目标；目标是等式就先查已有等式能否接上、
能否两边同时运算、化简后是否相同。

配套的**前向闭包**只做不分支的消去规则（蕴含消去 / 合取消去 / 等价消去 / 全称消去 / 否定消去），
把“一步可得”的结论先补进事实表，既保证简单目标一定被找到，也大幅减少搜索量。

两个工程细节值得记一笔：

- **id 对齐**：解算器为了内部记账会额外推导事实，若直接引用这些 id，重放时会对不上。
  解决办法是把闭包推导也记成“计划的一部分”（失败回溯时一并回滚），并按**作用域过滤**后内联进计划。
- **最终校验**：早期版本出现过“搜到了但目标根本没证到”的假成功。现在 `findProof` 返回前必须通过
  `verifyPlan`（在干净状态上重放并确认目标真的出现），否则一律判失败。

**当前战绩**（32 关，其中 **29 关玩家一定拿得到提示**：23 关手写与自动双份、3 关只有手写、3 关只有自动；
其余 3 关是开放练习）：解算器**独立搜出并通过验证 26 关**——
命题逻辑 16 关里解出 14 关（全部毫秒级）；代数 16 关里解出 12 关
（等式对称、等量代换、结合律/交换律实例化、三关化简、平方非负、解一元一次方程、复合式子上的公理应用）。

**解算器**（`node tools/solve-cli.mjs`）不是本项目的目标，而是**关卡质量的检验工具**：
它能独立搜出并验证 **26 / 32 关**的证明，与手写标准证明互为独立校验。
剩下 6 关（`L0-12`、`L0-16`、`L1-05`、`L1-12`、`L1-13`、`L1-14`）的共同瓶颈是搜索启发式：
需要在实例化公理后做多步等式/不等式推理，或需要对排中律做分支搜索。
这 6 关**全部有手写标准证明、玩家可解**（`L0-12`、`L1-13` 是开放练习，给路线不给逐步答案）——
解算器搜不出不等于关卡有问题。

未解出的 6 关的技术定位：

- `L0-12` 骑士与骗子、`L0-16`（`A → B ⊢ ¬A ∨ B`）：需要“按排中律分支 + 在支内先导出某支”的启发式。
  这两关在游戏里标为**开放练习**（给路线提示、不给标准答案）。
- `L1-05`、`L1-13`、`L1-14`：`∀E` 多次实例化后的组合仍偏大。
- `L1-12`（`|-3| = 3`）：需要“具体数值子式作桥梁”——要把 `-(-3)` 换成 `3`，
  而 `arith` 默认会把等式两边一起算成 `3 = 3`，反而丢了目标形状。

工程上值得记的坑：

1. **招法生成器不能被懒求值**：`moves()` 是生成器，而 `tryMove` 会改动状态，
   边搜边生成会让后面的候选基于被污染的状态（甚至已关闭的作用域）。现在先整体生成候选再逐个尝试。
2. **闭合招法必须真的得到目标**：`ring`/`arith` 会输出规范化式子，与目标写法不同却被当成成功。
   注意 `fkey` 是树字符串、`termKey` 是哈希，**两者不能直接比较**——这个类型混用曾让所有化简招法静默失效。
3. **实例化链同理**：`lemmaChain` 当初只保证“实例化成功”，不保证结果等于目标，于是满屏假分支。
4. **某一深度校验失败要继续加深**，而不是直接返回失败。
5. **无自由变量的目标不该用自由变量实例化**，否则全是 `? + -?` 这类无效组合。

性能上的坑：闭包每轮实例化全部公理，4 轮会让单关慢到 40 秒。现在是**一轮** + 事实集未变就跳过 +
按 (公理, 项) 缓存 + 只用目标/前提里出现过的项实例化；另外关卡可以用 `axiomPick` 只带这一题需要的公理，
搜证空间能小一个数量级（L1-16 从 2 万节点降到几个节点）。

曾试过「按规则代价给招法排序」，结果**反而更差**（L0-08 从 7 步变成搜不到）——顺序敏感的搜索不该粗暴重排，已回滚。

## 七、和已有项目的关系（调研摘要）

- **Lean 系**（mathlib4、lean4game、Robo、lean4game-logic）：严谨性天花板，但面向大学，
  关卡即 Lean 文件，用来做中学定理并不划算。
- **命题逻辑小项目**（logiko、turnstile、natural-deduction-game、fitch-checker）：交互范式成熟
  （Fitch 式编辑器 + 每步校验），但都停在"逻辑课"，没有数学公理与定理体系。
- **几何自动化**（GeoGebra Discovery 的 ShowProof、LeanGeo、Euclean）：能自动证几何题，
  但不是"玩家自己推理"的游戏。
- **中学形式化尝试**（omlib、Yalep）：把高中习题写进 Lean，尚未游戏化。

**本项目定位**：把"命题逻辑判定内核 + 中学公理体系 + 可玩关卡"接起来。既不依赖 Lean 工具链，
也不止步于逻辑玩具。下一步 L2（几何）可直接复用 Tarski 公理体系
（Mizar 的 Tarski Geometry Axioms、Avigad 等人的 Proof-checking Euclid 都可参考）。

## 八、交互上踩过的坑（已修）

- **早期版本用浏览器 prompt() 收集"取左/取右""代入哪个项"**。一旦浏览器屏蔽弹窗（返回 null），
  点规则会**静默无反应**——这正是 L0-04 被报的那个 bug。现在全部改成页面内的候选按钮 + 可手写输入，
  不再依赖任何弹窗。
- **显示公式时曾丢掉绑定名上下文**，导致形式为 ∀ 的公理实例显示成 x3 + (x2 + x1)。
  现在打印项一律携带上下文。
- **等于代换（=Sub）原先要求玩家手写结果式**。现在界面会枚举所有成立的替换（左右两侧 × 两个方向），
  逐个列出来点选。
- **空题设关卡载入后“没有可用事实”**（L0-02 证明 A → A、L0-11 证明 ¬¬A → A）：
  这两关一条题设都没有，规则又都要求“恰好 1 个前提”，点下去只得到前提数量报错，
  玩家看不出要先开子证明。现在事实面板会给出空状态提示，点 →I / ¬I / ⊥C 会给出
  “该假设什么”的引导卡 + 一键打开子证明。
- **选中析取点 ∨E 只会得到“需要恰好 3 个前提”**。玩家本来就需要先知道“要开哪两支”，
  现在会给出分情况讨论的引导卡（两支各自要推出什么 + 一键开始这一支）。
- **嵌套子证明里的事实会从界面上消失**：作用域写成 “H1|H2” 时，原先拿整串去和作用域栈比，
  永远不相等。现在逐段判断。这是解算器推嵌套子证明（L0-08、L0-10）时的标准形态，
  玩家照着提示走会撞上“要选一个界面上不存在的事实”。
- **排中律规则曾用 termEq 比较公式**（项与公式的比较器混用），导致 A ∨ ¬A 一律被拒。
  这类“比较器用错层次”的 bug 本项目出现过两次（另一次是 fkey 与 termKey 直接比较）。

## 九、已知边界

- L1 只覆盖**一阶可表达**的部分（有序域 + 绝对值 + 单调性）。实数完备性、极限、导数属二阶强度，
  未纳入，需以"公理层"方式处理。
- 集合部分目前只做属于关系与子集传递；完整集合论（幂集、映射、基数）留给后续。
- "骑士与骗子"（L0-12）是开放练习，只给思路提示，没有标准证明。
- Ring 只处理加减乘除（常系数）、平方与自然数幂；含绝对值或集合的式子请用等量代换手工推。
