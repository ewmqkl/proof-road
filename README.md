# 证明之路 · 从命题逻辑到代数定理

一个**零依赖**的网页小游戏：玩家在 Fitch 式证明台上点选前提、应用自然演绎规则，一步步推出中学数学课本里的结论。
每一步都由一个形式化内核实时校验，推错会被明确拒绝。

当前进度：**L0 + L1 共 32 关**，其中 **30 关有标准证明与逐步提示**（另 2 关是开放练习）；
L0 十六关**每一关都有分步新手引导**（可随时跳过）；**41 项成就**与 **34 条数学史条目**；
**存档系统**（自动存档 + 3 个手动槽位 + 导出/导入）；**155 项自动化测试全部通过**；
解算器能独立搜出并验证 **26 / 32 关**的证明。
可以打包成一个**自包含的 Windows 单文件 exe**（双击即用，目标机器不需要装任何运行时）。

## 一、Windows 桌面版：双击就能玩

不想开命令行、也不想开浏览器标签页的话，工作区里已经配好了一条打包流水线：

    node tools/build-desktop.mjs        # 产出 release/ProofRoad.exe（自包含单文件，约 42 MB）

打出来的是一个**真正的 Windows 应用**：有自己的窗口、任务栏图标和进度存档，双击即用。
目标机器**不需要装 .NET、不需要联网、不需要管理员权限**，Windows 10（1607+）与 Windows 11 的
32 位 / 64 位 / ARM64 都能跑。

它并不是另一个程序，只是给同一个网页套了一层壳：

| 层次 | 内容 | 大小 |
|---|---|---|
| 游戏本体 | `proof-road-standalone.html`（`src/` 下 16 个模块打成的一个文件） | 408 KB |
| 渲染 | 系统自带的 Microsoft Edge WebView2 内核 | 0（系统提供） |
| 外壳 | `desktop/` 下约 1000 行 C#，把 HTML 内嵌进 exe 并提供原生窗口 | — |
| 运行时 | .NET 9 自包含运行时，一起打进 exe | 42 MB |

三个值得一提的实现细节：

- **不往 exe 目录写任何东西**：存档、日志、窗口位置全部落在 `%LOCALAPPDATA%\ProofRoad`，
  所以 exe 放在 U 盘、只读目录或网络共享里也能跑。
- **本地回环端口是固定的**：游戏进度存在 localStorage 里，而 localStorage 按
  「协议 + 主机 + 端口」隔离——端口一变，存档就等于丢了。所以固定用 47100-47103，
  并且只监听 127.0.0.1，外网连不上，也不会弹防火墙。
- **没有 WebView2 也能玩**：自动退回 `msedge.exe --app=...` 的应用窗口模式；
  连 Edge / Chrome 都没有时，窗口里会直接给出运行时下载按钮。

构建参数、更新流程、兼容性矩阵与已知限制见 `desktop/README.md`；
给最终用户看的说明在 `desktop/使用说明.txt`。
## 二、先看结论：为什么不是"纯命题逻辑"

这是设计上最关键的一点，也是调研后必须纠正的前提：

| 想证明的东西 | 需要的逻辑强度 |
|---|---|
| A → A、(A∧B) → A、分情况讨论、反证法 | **命题逻辑**（L0） |
| x + y = y + x、合并同类项、移项、绝对值 | **一阶等词逻辑 + 有序域公理**（L1） |
| 三角形内角和、平行线性质 | 一阶几何公理（Tarski / Hilbert，L2） |
| 极限、导数、实数完备性 | 二阶 / 集合论强度（不可一阶化，只能作公理层） |

所以引擎做成**三段式**，这也是 Lean 等系统的实际做法：

    玩家操作（一阶层）              内核翻译（命题层）                 判定
    选前提 → 点规则         →   把这一步化成蕴含式          →   结构化校验（毫秒级）
    ∀E / →E / ∧I …               （前提1 ∧ 前提2 → 结论）          不通过就拒绝

内核只接受**可靠的局部推理**：一步的结论必须由所选前提按某条规则的形状精确导出。
"代数化简（Ring）"这类看起来自动的规则也不是黑箱：它把等式两边化归为**同一个多项式的规范形式**，
合法性完全由域公理（交换、结合、分配、逆元）保证，等价于把这些公理自动用了一遍。

## 三、怎么玩

**最省事的方式**是双击打包好的 `ProofRoad.exe`（见上一节）。想在开发时改代码即时看效果，
就用下面两种方式之一——浏览器的 ES 模块策略不允许 file:// 下加载模块，所以要起一个静态服务
（零依赖，只用 Node 内置模块）：

    node tools/serve.mjs        # 然后打开 http://127.0.0.1:8788

**或者完全不开服务**：直接双击 `proof-road-standalone.html`。
那是把所有模块内联进一个文件的构建产物（约 408 KB，零外部依赖），
用 `node tools/build-single.mjs` 生成、`node tools/check-standalone.mjs` 验证。

界面分四屏：**开始页 → 证明选择 → 证明台 → 档案室**，之间用斜向擦除过渡连接
（`prefers-reduced-motion` 下直接切换，不播动画）。屏幕可深链接：加 `#levels`、`#desk`
或 `#archive` 直接进对应屏。顶栏的导航是**关卡 / 档案室 / 存档 / 开始页**——
"存档"直接落到档案室的存档分页，不必先猜它在哪个标签里。

证明台上的操作：

1. 上方是**本关要证的结论**；
2. 左侧"可用事实"里**点选**若干条作为前提（再点一下取消）；
3. 右侧点一条**推理规则**：
   - 若这一步只有一种成立的结果，界面**直接替你落下**（例如 ∧E 取出的那一支正好是目标）；
   - 若有好几种可能，规则下方会出现**候选结果**按钮（如"取左边 / 取右边"），点一个即可；
   - 也可以自己在候选栏里**手写项或结果式**（回车确认），用来做中间步骤；
4. 通过就生成一条新的已推导事实；不通过会给出**具体原因**；
5. "打开假设"用于子证明（蕴含引入 / 否定引入 / 反证法都要先开子证明）；
6. "提示"按本关标准证明逐步给提示；"查看本关公理表"可展开公理；
7. "数学史 · 这一关的来历"展开本关相关的史话（在哪一年、谁做的、为什么会有这条规则）；
8. "本关引导"可以随时重新打开这一关的分步新手引导；
9. "重开本关"清空这一关推到一半的现场，从第一步重来（要连点两次确认）。

**分情况讨论（∨E）怎么走**：选中一条析取再点 ∨E，界面会给出一个**引导卡**，
写清"两支各自要推出什么"，每支旁边有"开始这一支"按钮，点了就自动替你打开对应的子证明。
一支推完合上（用 →I / ¬I / ⊥C）后，回到引导卡会看到它标成 ✓；两支都 ✓ 之后，
再选中那条析取与两条结论点 ∨E 就收尾。左下角还有**子证明指示器**（"1. H1：A ／ 2. H2：¬B"），
随时能看到自己处在第几层、以及合上时该收哪一层。

**排中律**（A ∨ ¬A）不需要自己写式子：点排中律，界面会列出可用的取法；
如果目标形如 A ∨ B，它会自动挑出该对哪个命题取排中。

**证明记录**里子证明内的事实会按层次缩进，已经合上的整段变灰并标注"已合上"，
避免误以为还能引用。

进度存在浏览器 localStorage，可随时重置；关掉再打开会自动接着上次的现场继续（见 4.4）。

### 关卡一览

**L0 命题逻辑训练场（16 关）**：引用前提 → 蕴含引入 → 假言推理 → 合取引入/消去 →
析取引入/分情况讨论 → 否定引入 → 反证法 → 逆否命题 → 双重否定 → 骑士与骗子 →
三段论 → 等价引入 → 综合题（多步推理、排中律分情况）。
**每一关都有单独写的分步引导（4 – 8 步）与关联的数学史条目。**

**L1 代数证明（16 关）**：等式的对称/传递/等量代换 → 公理实例化（交换律、结合律）→
两边同时运算 → 合并同类项 → 完全平方 → 平方差 → 移项解方程 → 平方非负 → 绝对值 →
一次函数单调性 → 集合属于关系 → 综合题（复合式子上的公理应用）。
L1 没有逐关手写引导，但"本关引导"会按关卡数据现算一份简版引导；每关同样有关联史话。

## 四、新手引导、成就系统与数学史

这三块是同一件事的三个面：**让人知道下一步该干什么**（引导）、**让做过的事留下痕迹**（成就）、
**让每一步都接得上数学史**（史话）。

### 4.1 分步新手引导（可跳过）

第一次进入证明台时，会先弹一段**全景导览**（11 步），逐个高亮证明台上的每一块：
目标卡、题设、可用事实、推理规则、候选面板、子证明与作用域指示器、证明记录、状态栏、提示与公理表。
导览看完后（或跳过后）会接着播**本关的分步引导**。

L0 的十六关**每一关都单独写了引导**（4 – 8 步，合计 100 步），讲的不是"点这里"，
而是"为什么这一步是这样"：例如 L0-07 会说明为什么只能先选那条析取、两支各自要推出什么；
L0-10 会强调嵌套子证明里"合上必须从最内层开始"；L0-16 会先点出"¬A ∨ B 与 A → B 其实是一回事"。

实现上有几个刻意的选择：

- **不挡操作**：遮罩 `pointer-events: none`，引导期间证明台照常能点。
  聚光效果是用目标元素自己的 `box-shadow: 0 0 0 9999px rgba(0,0,0,.62)` 做的——
  目标抬到遮罩之上，周围整片压暗，不需要额外的"挖洞"图层。
- **能等玩家动手**：步骤可以声明自己在等什么动作（`advance: 'assume' | 'step' | 'solved'`），
  玩家真的打开了子证明、真的落下一步之后，引导才前进；不想动手也可以直接点"下一步"。
- **随时可跳过，且记得住**：浮标上有"跳过引导"（Esc 同效），跳过后这一关不再自动弹；
  想重看点"本关引导"，想整体关掉在档案室侧栏切一下，重置进度后恢复默认。
- **L1 不写死**：没有手写引导的关卡由 `buildFallbackGuide()` 从关卡数据现算一份简版引导
  （目标是什么形状、有哪些公理要先实例化、这一关能用的规则是哪些），所以"本关引导"按钮
  在任何一关都有东西可看。

引导的数据与运行时是分开的：`src/data/tutorial.js` 只有纯数据，
`src/ui/tutorial.js` 只管浮标与高亮，两者都不碰证明状态。

### 4.2 成就系统（41 项）

成就分五组：**推进战绩**（通关数、L0/L1 全清）、**推理技法**（每条规则至少用过一次、
用过 12 种 / 全部 21 种规则）、**自律挑战**（零提示通关、一气呵成、三层嵌套子证明、
"错误是老师"——被拒绝 20 次）、**证明台**（展开公理、撤销、提示、看引导、累计 100 步）、
**数学史**（读史话、以及若干与史实挂钩的成就，如"与布劳威尔唱反调"= 证出双重否定消去、
"无名变量"= 读完 de Bruijn 的史话并通关嵌套子证明那一关）。

判定是**纯函数**：`src/core/achievements.js` 接收一份"玩家档案"（从存档算出），
返回每条成就的解锁状态与进度。界面只负责把事件记成档案（落子、提示、撤销、被拒绝、
子证明层数、规则使用次数、读过的史话），不参与判定。所以：

- 同一份存档必然得到同一组成就，测试可以直接构造档案来验证（包括"只增不减"这条性质）；
- `noHint` / `clean` 这类"表现型"标记是**首次通关那一刻盖章**的，
  之后再回来玩、或者用提示重玩，已经拿到的成就不会被撤销；
- 加一条成就只需要在 `src/data/achievements.js` 里写一个 `check` 和一个 `progress`，
  不用改界面。

解锁时会弹出提示条（`成就解锁 · 银 / 名字 / 条件`），档案室里能看到全部成就、
完成度进度条，以及"最接近解锁的四条"。

### 4.3 数学史：每一关的来历

`src/data/math-history.js` 里有 **34 条史话**，按六个时代分组：

| 时代 | 覆盖 |
|---|---|
| 古代：从公理到证明 | 《几何原本》与"等量加等量"、亚里士多德的三段论与排中律、芝诺与希帕索斯的归谬法、素数无穷、麦加拉学派的费罗条件句、《原本》第二卷里的平方差 |
| 东方与中世纪 | 《九章算术》"方程"章的消元与负数、花拉子米的 al-jabr 与 al-muqābala（algebra 一词的来历、配方的几何做法） |
| 符号化 | 韦达用字母代替数、笛卡尔的 x/y/z 约定、帕斯卡论"几何精神"、莱布尼茨的"让我们来计算一下" |
| 逻辑的数学化 | 布尔的逻辑代数、德摩根律、柯西与魏尔斯特拉斯的严格化（顺带解释绝对值的竖线是魏尔斯特拉斯 1841 年引入的）、皮亚诺的量词记号、弗雷格《概念文字》、康托尔的集合论 |
| 基础与形式化 | 希尔伯特《几何基础》、怀特海与罗素的《数学原理》与 1+1=2、布劳威尔与海廷的直觉主义、希尔伯特纲领与哥德尔不完备定理、**根岑的自然演绎**、**费奇的竖线**、ZFC 的外延公理、塔尔斯基的一阶几何（L2 预告） |
| 现代 | 斯穆里安的骑士与骗子岛、**德布鲁因的 AUTOMATH 与"无名变量"**、四色定理、开普勒猜想与 Flyspeck、Lean/mathlib 与 Xena 计划 |

几点内容上的取舍：

- **只写可以核对的史实**：年份、人物、文献名、结论都写具体，不写"很久以前"。
  写错的代价很高（这是给人当知识点读的），所以每条都标了年份与出处级别的信息。
- **和本作真正相关**：两条最"近"的史话是根岑（自然演绎的引入/消去规则配对，
  正是证明台上 21 条规则的来源）与德布鲁因（1972 年的 de Bruijn 索引，
  正是本作内核为了避免"替换抓错变量"所使用的那套表示法）；
  四色定理那一条讲的是分情况讨论的极端形态，正好呼应 L0-07。
- **不粉饰争议**：排中律那两条会明确写出直觉主义者的反对立场，
  并指出 L0-11 证出的双重否定消去在直觉主义逻辑里并不成立——这不是"谁算错了"。

每关的史话有两个入口：证明台下方的"数学史 · 这一关的来历"（展开即记为已读），
以及档案室的"数学史"分页（按时代分组、可展开全文、可直接跳到相关关卡）。

### 4.4 存档：自动存档 + 3 个手动槽位 + 导出/导入

**四个入口**，因为"藏在档案室第三个小标签里"等于没有：
顶栏的「存档」（证明选择与证明台各一个）、证明选择右侧详情面板的「存档 / 读档」、
证明台下方的「存档 / 读档」，以及档案室 → 存档分页本身。

存档分三层，粒度不同，互相不干扰：
| 层 | 存什么 | 什么时候写 | 在哪 |
|---|---|---|---|
| **自动存档** | **每一关的证明现场**（事实表、子证明作用域、编号计数） | 每落一步、每次撤销、每次展开公理 | `lpg.save.auto` |
| **进度** | 通关记录、统计、规则使用、成就、史话阅读、引导偏好 | 每次事件 | `lpg.done` / `lpg.stats` / … |
| **手动槽位（3 个）** | 进度 + 当前这一关的现场，可命名 | 玩家点"存入此槽" | `lpg.save.slots` |

几个设计上的取舍：

- **现场是“逐关”的，不是一个全局现场**。玩家在关卡索引里东看西看时，
  不该把别的关推到一半的东西弄丢，所以 `lpg.save.auto` 里是 `{ 关卡 id → 现场 }` 的映射，
  回到哪一关就装回哪一关的现场（状态栏会写明"已恢复到上次的现场：这一关已经推了 N 步"）。
- **启动时回到上次那一关**：`bootLevelId()` 取自动存档里最后动过、且还留着现场的那一关；
  没有现场就从第一关开始。因为有了这个行为，证明台上必须给一个出口——
  "重开本关"（连点两次确认）会清掉这一关的现场、从第一步重来。
- **过关即清现场**：推完的关卡不再保留现场，否则下次进去会一开门就显示"已完成"。
- **刷新洗不掉表现**：从现场接着推时走的是 `noteResume()` 而不是 `notePlay()`，
  **不清空本次尝试的提示/撤销/报错计数**——否则刷新一次就能把"零提示通关"洗出来，
  那条成就就没有意义了。
- **现场要校验题设**：把现场装回状态前会逐个比对题设与公理的结构（`fkey`）。
  如果存档来自旧版本的关卡表，宁可拒绝并说明原因，也不装出一个"题设对不上"的诡异局面。
  被拒绝时只丢现场，通关进度不受影响。
- **导入是唯一的不可信输入边界**：`parseSave()` 对每个字段做类型检查与降级，
  坏数据永远不会污染存档。格式带 `format` 标记与 `version`，为后续升级留了迁移位置。
- **不用浏览器弹窗**：所有破坏性操作（读取槽位、删除槽位、清空进度、重开本关）
  都是"再点一次确认"的两次点击，按钮会变色换文案并在 4 秒后自动解除——
  这个项目早期吃过 `prompt()` 被拦截后静默无反应的亏，不再依赖任何弹窗。

**导出与导入**：导出会生成一份带缩进的 JSON（`proof-road-L0-13-202610091840.json`），
既可以下载成文件，也可以点"存档文本"取出一段文字自己复制；导入两种都支持
（选择文件，或把文本粘进文本框）。**下载兜底**：某些环境（`file://`、部分内嵌浏览器）
不允许直接下载，所以文本通道是必备的，不是装饰。

存档槽**不会被"重置进度"删除**——那是玩家的备份，要删请单独点"删除"。
重置会清掉的是：进度、统计、成就、史话阅读、引导偏好与自动存档现场。

## 六、内核设计要点

**de Bruijn 绑定**：量词不存变量名，只存索引（0 = 最内层）。因此"替换抓错变量"在**结构上不可能发生**，
不是靠小心，而是靠表示法。形如 ∀y, w + y = y + w 的结果由 instAll / closeAt 直接算出。

**作用域纪律（Fitch 风格）**：每条事实都记录它依赖了哪些假设。
蕴含引入只能合上**最内层**假设，结论仍带外层假设标签；合上后，依赖该假设的事实立即失效，不能再被引用。
所以嵌套子证明（比如逆否命题）必须真的嵌套着做，不能跨层取巧。

**形状精确匹配**：规则检查公式的形状。蕴含消去要求前提中有 A → B 且另一个前提与 A α 等价；
析取消去要求两支蕴含的结论**完全相同**。α 等价对项也成立（a = b 与 b = c 能正确串成 a = c）。

**量词实例化**：全称消去必须给出项，比如把 ∀a,b. a + b = b + a 用到 x、y 上——
这正是数学里"把普遍规律用到具体对象"的动作。界面提供"展开全称公理"一键生成候选实例。

## 七、自动搜证明（解算器）

除了手写关卡，工程里带一个**自动定理证明搜索器**：给一个定理（+可用规则 +公理集），它会自己把证明找出来，
并且**每一步都立刻用内核验证**，最后还会把整份计划在干净状态上重放一遍确认达阵。

    node tools/solve-cli.mjs                     # 给全部 28 关搜证明
    node tools/solve-cli.mjs L0-10 --depth 10    # 指定关卡与深度上限
    node tools/gen-proofs.mjs                    # 生成/刷新 src/data/found-proofs.js

**做法**：反向链接（从目标倒推）+ 迭代加深 + 节点/时间预算。招法按“目标形状”生成：
目标是蕴含就先假设前件再证后件；目标是合取就分成两个子目标；目标是等式就先查已有等式能否接上、
能否两边同时运算、化简后是否相同。

配套的**前向闭包**只做不分支的消去规则（蕴含消去 / 合取消去 / 等价消去 / 全称消去 / 否定消去），
把“一步可得”的结论先补进事实表，既保证简单目标一定被找到，也大幅减少搜索量。

两个工程细节值得记一笔：

- **id 对齐**：解算器为了内部记账会额外推导事实，若直接引用这些 id，重放时会对不上。
  解决办法是把闭包推导也记成“计划的一部分”（失败回溯时一并回滚），并按**作用域过滤**后内联进计划。
- **最终校验**：早期版本出现过“搜到了但目标根本没证到”的假成功。现在 `findProof` 返回前必须通过
  `verifyPlan`（在干净状态上重放并确认目标真的出现），否则一律判失败。

**当前战绩**（32 关，其中 **29 关玩家一定拿得到提示**：23 关手写与自动双份、3 关只有手写、3 关只有自动；
其余 3 关是开放练习）：解算器**独立搜出并通过验证 26 关**——
命题逻辑 16 关里解出 14 关（全部毫秒级）；代数 16 关里解出 12 关
（等式对称、等量代换、结合律/交换律实例化、三关化简、平方非负、解一元一次方程、复合式子上的公理应用）。

**解算器**（`node tools/solve-cli.mjs`）不是本项目的目标，而是**关卡质量的检验工具**：
它能独立搜出并验证 **26 / 32 关**的证明，与手写标准证明互为独立校验。
剩下 6 关（`L0-12`、`L0-16`、`L1-05`、`L1-12`、`L1-13`、`L1-14`）的共同瓶颈是搜索启发式：
需要在实例化公理后做多步等式/不等式推理，或需要对排中律做分支搜索。
这 6 关**全部有手写标准证明、玩家可解**（`L0-12`、`L1-13` 是开放练习，给路线不给逐步答案）——
解算器搜不出不等于关卡有问题。

未解出的 6 关的技术定位：

- `L0-12` 骑士与骗子、`L0-16`（`A → B ⊢ ¬A ∨ B`）：需要“按排中律分支 + 在支内先导出某支”的启发式。
  这两关在游戏里标为**开放练习**（给路线提示、不给标准答案）。
- `L1-05`、`L1-13`、`L1-14`：`∀E` 多次实例化后的组合仍偏大。
- `L1-12`（`|-3| = 3`）：需要“具体数值子式作桥梁”——要把 `-(-3)` 换成 `3`，
  而 `arith` 默认会把等式两边一起算成 `3 = 3`，反而丢了目标形状。

工程上值得记的坑：

1. **招法生成器不能被懒求值**：`moves()` 是生成器，而 `tryMove` 会改动状态，
   边搜边生成会让后面的候选基于被污染的状态（甚至已关闭的作用域）。现在先整体生成候选再逐个尝试。
2. **闭合招法必须真的得到目标**：`ring`/`arith` 会输出规范化式子，与目标写法不同却被当成成功。
   注意 `fkey` 是树字符串、`termKey` 是哈希，**两者不能直接比较**——这个类型混用曾让所有化简招法静默失效。
3. **实例化链同理**：`lemmaChain` 当初只保证“实例化成功”，不保证结果等于目标，于是满屏假分支。
4. **某一深度校验失败要继续加深**，而不是直接返回失败。
5. **无自由变量的目标不该用自由变量实例化**，否则全是 `? + -?` 这类无效组合。

性能上的坑：闭包每轮实例化全部公理，4 轮会让单关慢到 40 秒。现在是**一轮** + 事实集未变就跳过 +
按 (公理, 项) 缓存 + 只用目标/前提里出现过的项实例化；另外关卡可以用 `axiomPick` 只带这一题需要的公理，
搜证空间能小一个数量级（L1-16 从 2 万节点降到几个节点）。

曾试过「按规则代价给招法排序」，结果**反而更差**（L0-08 从 7 步变成搜不到）——顺序敏感的搜索不该粗暴重排，已回滚。

- **引导**（13 项 + 界面集成 20 项）：L0 每关至少 4 步、步骤 id 唯一、动作类型合法；

  因为打桩 DOM 看不到只写在 `index.html` 里的元素，删掉了也没人发现。
  界面集成测试则真的走一遍：自动弹出 → 上一步/下一步/跳过 → 跳过过的关卡不再弹 →
  "本关引导"能重开 → 打开子证明与落子会推动引导 → 读过史话会解锁成就 →
  通关会弹成就提示 → 档案室三个分页都渲染出内容 → 引导开关能关能开 → 重置清空一切。
- **存档**（16 项 + 界面集成 22 项）：现场序列化后**在每一个中间步骤上**都能装回去并接着推完
  （逐个切点做、不是只测一个）；题设被改过的存档必须被拒绝且不污染状态；
  缺胳膊少腿的存档不崩；坏 JSON / 认错格式 / 更高版本 / 空存档各有可读原因；
  进度归一化会吃掉脏数据；自动存档逐关互不覆盖、空现场不入档；
  界面层则验证：每步自动存档 → 重进同一关现场回来 → 过关清现场 →
  "重开本关"两次点击 → 槽位存取 → 导出/导入往返 → 空槽位/坏数据不动进度 →
  重置进度保留槽位 → 删除槽位要两次点击 → 四个存档入口各自直达存档分页。
- **关卡选择**（3 项）：切层级、在另一层里选关并开始证明、详情面板上的存档入口。
  这三条是为"点 L1 没反应"那个 bug 补的回归测试。

关于测试隔离有一条值得记的坑：各测试文件共用同一个 app 实例（模块只求值一次），
而自动存档会**跨测试**把上一关推到一半的现场带回来。所以界面测试统一用
`cleanLoad()`（先清存档再载入关卡）拿确定性的初始局面，
而不是去依赖"跑在我前面的是哪个文件"——那样写出来的测试会在某次重排后集体翻车。

## 十、交互上踩过的坑（已修）

- **早期版本用浏览器 prompt() 收集"取左/取右""代入哪个项"**。一旦浏览器屏蔽弹窗（返回 null），
  点规则会**静默无反应**——这正是 L0-04 被报的那个 bug。现在全部改成页面内的候选按钮 + 可手写输入，
  不再依赖任何弹窗。
- **显示公式时曾丢掉绑定名上下文**，导致形式为 ∀ 的公理实例显示成 x3 + (x2 + x1)。
  现在打印项一律携带上下文。
- **等于代换（=Sub）原先要求玩家手写结果式**。现在界面会枚举所有成立的替换（左右两侧 × 两个方向），
  逐个列出来点选。
- **空题设关卡载入后“没有可用事实”**（L0-02 证明 A → A、L0-11 证明 ¬¬A → A）：
  这两关一条题设都没有，规则又都要求“恰好 1 个前提”，点下去只得到前提数量报错，
  玩家看不出要先开子证明。现在事实面板会给出空状态提示，点 →I / ¬I / ⊥C 会给出
  “该假设什么”的引导卡 + 一键打开子证明。
- **选中析取点 ∨E 只会得到“需要恰好 3 个前提”**。玩家本来就需要先知道“要开哪两支”，
  现在会给出分情况讨论的引导卡（两支各自要推出什么 + 一键开始这一支）。
- **嵌套子证明里的事实会从界面上消失**：作用域写成 “H1|H2” 时，原先拿整串去和作用域栈比，
  永远不相等。现在逐段判断。这是解算器推嵌套子证明（L0-08、L0-10）时的标准形态，
  玩家照着提示走会撞上“要选一个界面上不存在的事实”。
- **排中律规则曾用 termEq 比较公式**（项与公式的比较器混用），导致 A ∨ ¬A 一律被拒。
  这类“比较器用错层次”的 bug 本项目出现过两次（另一次是 fkey 与 termKey 直接比较）。
- **引导的读文件顺序坑**：界面代码里的 `$('xxx')` 写错一个字母，运行时就是“点了没反应”，
  而无浏览器测试用的是打桩 DOM——`getElementById` 对任何 id 都会返回一个空元素，
  这类错误根本报不出来。现在有一条静态对照测试，把 `app.js` / `tutorial.js` 里所有
  `$('...')` 字面量与 `index.html` 的 id 表逐个核对。
- **假 DOM 里的层级陷阱**：打桩 DOM 的元素是扁平的，`#coach > #coach-card > #coach-hist`
  这层父子关系并不存在，所以「断言浮标里有没有某段文字」必须查具体元素，
  不能像真实 DOM 那样从容器一路 `flatten` 下去——这条也是被测试逼出来的。
- **点 L1 标签没反应**（玩家报的）。`renderSelect()` 里有一行
  `pickedTier = picked.tier`，本意是"第一次进这一屏时用当前关卡兜底"，
  却写成了无条件覆盖：点 L1 标签 → 设 `pickedTier = 'L1'` → 立刻重画 → 被改回 'L0'，
  网格还是 L0，玩家看到的就是"这个标签是坏的"。
  根因是两个变量被混为一谈：`pickedTier` 是**正在浏览哪一层**，
  `pickedId` 是**详情面板里选中的是哪一关**，两者可以不在同一层。
  现在兜底只在"还没选中过"时生效，切层时顺带把详情面板也切到那一层的第一个关卡。
  补了三条回归测试（切 L1、在 L1 里选关并开始证明、切回 L0）——
  这类"点了没反应"的 bug 靠无浏览器测试是能抓住的，前提是有人真的去点它。
- **打桩 DOM 读不到写在子元素里的文字**。真实 DOM 里 `button.textContent` 会包含
  子 `span` 的文字，打桩元素却各存一份，于是"按按钮文字找按钮"的测试全部找不到。
  现在测试助手统一用 `labelOf()`（等价于对整棵子树取文字）来匹配，两边行为才对得上。
- **图标画成了字母 E**（玩家报的"图标怎么变回来了"）。`tools/make-icon.mjs` 的注释写着
  "存在量词 ∃"，坐标却把竖笔放在**左边**（x 0.255..0.350）——那是字母 E；
  ∃ 是 E 的镜像，竖笔必须在右边（0.650..0.745）。这类"注释和代码各说各话"的错误
  肉眼很难发现：图标小、又是单色，看上去都像个 E。
  现在坐标旁边写死了方向说明，并加了一条测试直接读几何、断言竖笔在右半边
  （连同"ICO 必须是 7 档 32bpp DIB 条目""csproj 必须同时挂上文件图标与内嵌资源"一起测）——
  不用跑起 exe 就能拦住这类回归。

## 十一、已知边界

- L1 只覆盖**一阶可表达**的部分（有序域 + 绝对值 + 单调性）。实数完备性、极限、导数属二阶强度，
  未纳入，需以"公理层"方式处理。
- 集合部分目前只做属于关系与子集传递；完整集合论（幂集、映射、基数）留给后续。
- "骑士与骗子"（L0-12）是开放练习，只给思路提示，没有标准证明。
- Ring 只处理加减乘除（常系数）、平方与自然数幂；含绝对值或集合的式子请用等量代换手工推。
- 新手引导是**逐关手写在 L0** 的；L1 走自动生成的简版引导，只讲"结论什么形状、
  哪些公理要先实例化、这一关能用哪些规则"，不会有 L0 那种针对具体难点的逐步讲解。
- 成就系统没有服务器，也没有"反作弊"：存档就在 localStorage 里，
  想改随时能改。它的定位是给自己看的里程碑，不是排行榜。
- 数学史条目是**人写的知识点**，只保证写出来的年份、人物、文献可核对；
  它不是史学论述，每条末尾也不附参考文献。真要引用请回到原始文献。
- 存档只在**本机**：没有账号、没有云同步。跨机器请用"导出存档文件 / 存档文本"手动搬。
  桌面版的存档随 `%LOCALAPPDATA%\ProofRoad` 走，网页版随浏览器站点数据走。
- 存档能**完整还原证明现场**（事实表、子证明作用域、编号），但不会还原"选中了哪几条事实""史话卡是不是展开着"这类纯界面状态——
  回到那一关时是干净的界面加上原来的推理记录。
- 存档格式带 `version`，升级路径留在 `migrate()` 里，但**目前只有 v1**：
  真改了关卡数据的话，旧现场会被拒绝（只丢现场、不丢进度），这一点是刻意的。
